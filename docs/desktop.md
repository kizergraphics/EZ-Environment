# Windows portable desktop

**Current biome upgrade:** see [release notes](RELEASE_NOTES.md) and [biome validation](BIOME_UPGRADE.md). The performance and release history farther below describes the earlier September 4 build. Its High/soak measurements do not apply to the new biome compositions. Set `EZ_PORTABLE_BENCH=0` to run the portable smoke without another camera benchmark.

The desktop build is local and unpublished. `npm run desktop:pack` produces `release/EZ-Environment-1.1.0-Portable.exe`; no installer or Node.js installation is required on the destination Windows x64 machine. Keep the EXE in a writable folder. The adjacent `EZ Environment Data` folder stores browser settings and local presets and can travel with the executable. The Chromium runtime is unpacked to the Windows temporary directory during launch.

## Commands

| Command | Purpose |
| --- | --- |

| `npm run desktop:dev` | Start the local Vite server and the desktop shell with hot reload. |

| `npm run test:desktop` | Check request policy, path confinement, CSP, and packaging boundaries. |
| `npm run test:desktop:smoke` | Exercise real Electron loading, renderer isolation, network denial, and persisted settings. |

| `npm run test:desktop:portable` | Copy the single EXE to an isolated path with spaces, launch it, verify its adjacent profile and persistence across restart, and capture a screenshot. |

The portable binary is unsigned and runs with the user's ordinary permissions. It does not register an installer, updater, startup service, or remote connection. Normal export downloads use a Save dialog. The original reusable tree library retains its existing package entry points; only the packaged application receives `desktop/main.cjs` as its main entry.

## Runtime security and offline assets

Bundled resources are served through the secure `ez-environment://app/` protocol. The renderer is sandboxed, with context isolation and web security enabled and Node.js disabled. File path resolution is confined to the built renderer directory. Remote/file fetches, external navigation, additional windows, webviews, and permission requests are denied. Development allows only its exact loopback Vite origin.

Draco decoder files are copied from the pinned Three.js package by `scripts/desktop-prepare.mjs`; app builds and desktop development run this step automatically. Licenses for EZ-Tree, Three.js, Draco, and Electron are bundled under `/licenses/`, and bark texture attribution remains under `/textures/LICENSE.md`. `desktop/resources/THIRD-PARTY-NOTICES.md` records the provenance available in the upstream source, including asset categories with no independent per-file notice.

## Recorded baseline

Before changing the renderer, both original upstream builds passed at commit `dcf309bd86bd521083d9c70f01f2de45fdc7c457`. The baseline harness injects seed 18427, measures the stationary original scene at 1920 × 1080/DPR 1 after 10 seconds of warm-up for 30 seconds, and records a screenshot. This is a stationary baseline, not the later camera-replay gate.

The real Electron 44.2.0 run used the NVIDIA RTX 3080 through D3D11, driver 32.0.15.9186. Average frame time was 13.328 ms, p95 13.4 ms, and p99 13.5 ms, with approximately 626 draw calls and 2.352 million triangles per frame. The monitor-limited run was approximately 75 FPS. Reports and the screenshot are under `artifacts/baseline/electron/`. The earlier headless Chromium run used SwiftShader and must not be treated as hardware performance evidence.

The dependency audit at initial packaging reported 20 development/build dependency advisories (9 moderate and 11 high), inherited from the upstream Vite 5/declaration toolchain. `npm audit --omit=dev` reported zero advisories. Build-tool upgrades were deferred during feature integration to keep the build baseline stable; the packaging dependency lock includes Electron 44.2.0, electron-builder 26.15.3, and Playwright 1.62.1. This audit result is not a claim that all possible runtime vulnerabilities are excluded.

## Hardware regression harness

`node scripts/desktop-benchmark.mjs` measures all four editor modes and runs the full circular camera replay for Low, Medium, and High environment quality. It uses a 1920 × 1080 drawing buffer at DPR 1, warms shaders first, records actual NVIDIA GPU timer queries when available, and runs five warm-up plus twenty changing-seed regenerations. `--draws` separately attributes primary and shadow draw calls to environment content, terrain, sky, and the full scene. `--chunk-size=64` changes only the runtime chunk-size option for comparison; partition changes can change seeded placement records and counts. `--lifecycle` exercises fresh initialization, regeneration, repeated disposal, and cancellation during initialization.

Use `--soak --minutes=30` for a live High-quality longevity run with checkpoints every regeneration/replay cycle. Its final assertions check repeated-seed determinism, zero reported errors, and geometry/texture/shader-program counts stable within one resource after five warm-up cycles. An interrupted run is not a completed soak. Subsequent builds cannot corrupt running tests: every harness invocation copies `dist` to an isolated temporary snapshot and records the JavaScript bundle hashes with the report. Existing reports are copied into `artifacts/performance/history/` before replacement. The desktop shell's asset-root override is available only when unpackaged and is ignored by distributed EXEs.

GPU frame timer deltas can be noisy under desktop-compositor scheduling. `--incremental` retains ordinary on/off observations for transparency. `--gpu-batch` measures repeated fixed-camera renders in alternating terrain/vegetation-on and -off batches to amortize scheduling overhead. These batched timings are GPU microbenchmarks, not application FPS or proof of worst-case timing at every camera position. Reports and screenshots are written under `artifacts/performance/` and identify their measurement scope.

`--gpu-component` performs the warmed full-camera replay with the hero tree and scenic forest hidden while preserving environment content, terrain, sky, lights, fog, and shadow policy. It directly queries that component's GPU render time rather than subtracting separately scheduled frames. `--determinism` runs fifty changing-seed generations with two-second camera replays and compares immediate/post-replay raw record hashes, worker-reported hashes, and options snapshots. Raw hashing is intentionally intrusive CPU diagnostics and is not a frame-time acceptance measurement.

The isolated 2026-09-04 candidate run (`index-DgctAMMF.js`, SHA-256 `15ec7cd2f3946d5ae4140fcf1be66a0589dfa633053cacd0f381cecfe9ebec30`) passed the measured frame/update/p95-draw gates on the RTX 3080. Low/Medium/High camera-replay frame-time p95 was 14.0/14.1/13.9 ms, and environment-update p95 was 0.1 ms for each. Environment-only draw p95 was 77/94/94; Medium and High peaked at 103, so this is explicitly not a maximum-at-every-camera guarantee. The full-scene draw p95 was 95/110/110. Twenty measured changing-seed regenerations held exactly 98 geometries, 15 textures, and 22 shader programs after five warm-up cycles. `artifacts/performance/benchmark-report.json` records all six mode/quality cases, actual GPU query timings, and zero renderer errors. Subsequent save/export-only fixes require their own final portable smoke evidence and must not be silently relabeled as this measured bundle.
